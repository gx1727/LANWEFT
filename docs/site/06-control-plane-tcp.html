线上字节示例（抓包视角）

下例是一个完整可复核的控制帧（login，msg_type = 0x01）的线上字节。 本例用于锁定字节序与校验区间；实现必须与之逐字节一致。

线上偏移字节（hex）可打印字符字段
0x00–0x03 4C 41 4E 57 LANW magic —— 协议魔数，位于线上最前 4 字节；小端序解读的 u32 值为 0x574E414C
0x04–0x07 22 00 00 00 " frame_len = 34（16 帧头 + 18 消息体）
0x08–0x0B D3 E3 D5 CC ··· header_crc32 —— 小端序解读的 u32 值为 0xCCD5E3D3
0x0C 01 ··· msg_type = 0x01（login）
0x0D 00 ··· flags —— 保留位
0x0E 00 ··· body_version = 0
0x0F 00 ··· reserved —— 保留字节
0x10–0x21 00 03 00 00 00 00 00 00 06 00 64 65 76 2D 41 31 00 00 ······dev-A1·· body（18 字节）—— login 定长区 8 字节 ‖ device_id（06 00 + "dev-A1"）‖ token（00 00，空串）
magic 的字节序陷阱：magic 是 u32，按小端序存放 —— 线上字节为 4C 41 4E 57，不是 57 41 4E 4C。 抓包工具按字节显示时应当看到 4C 41 4E 57； 按 u32 解读时应当得到 0x574E414C。 比对必须按线上字节序 4C 41 4E 57 判断，不得按 0x574E414C 的字节序反推。

接收方的校验步骤（规范性）

  1. 比对线上字节 4C 41 4E 57（即 magic == 0x574E414C）；
  2. 计算 crc32(字节[0:8] ‖ 字节[12:16]) 并与 header_crc32 比对 （本例被校验的 12 字节为 4C 41 4E 57 22 00 00 00 01 00 00 00）；
  3. 校验 frame_len ∈ [16, max_frame_len]；
  4. 以上全部通过后，才必须按 frame_len 读满 frame_len − 16 字节的帧体。
可复核性：本例的 header_crc32 由 CRC-32/ISO-HDLC（zlib crc32） 对上述 12 字节计算得出，实现必须能复核出 0xCCD5E3D3。

帧级错误处理

情况处理
magic != 0x574E414C判定失步，丢弃并关闭连接（MAGIC_MISMATCH）
header_crc32 校验失败判定失步，丢弃并关闭连接（HEADER_CRC_INVALID）
frame_len == 0判定失步，丢弃并关闭连接（FRAME_LEN_INVALID；读取指针无法推进）
frame_len > max_frame_len判定失步，丢弃并关闭连接（FRAME_LEN_INVALID；帧边界不可信）
frame_len < 16判定失步，丢弃并关闭连接（FRAME_LEN_INVALID；帧长不足以容纳帧头）
msg_type 未知按「未识别消息必须忽略」丢弃该帧，连接保持
定长区长度不足按 SERIALIZATION_ERROR 丢弃该帧，连接保持
变长区长度越界按 SERIALIZATION_ERROR 丢弃该帧，连接保持
reserved ≠ 0必须忽略，不得视为错误，连接保持
定长区数值违反取值约束按 SERIALIZATION_ERROR 丢弃该帧，连接保持

帧同步与失步处理（规范性）

接收方必须按下列顺序校验帧头，任一不通过即判定失步（desync）：

  1. magic == 0x574E414C；
  2. header_crc32 校验通过；
  3. frame_len ∈ [16, max_frame_len]。
  • 失步必须导致：丢弃该连接上尚未解析的全部数据、关闭连接， 并以 PROTOCOL 类错误码记录（MAGIC_MISMATCH / HEADER_CRC_INVALID / FRAME_LEN_INVALID，见 19 章）。
  • 失步后不得在本连接上继续解析任何帧，不得继续执行协议状态机。
  • 受影响会话必须按 13 章「断线重连」恢复 —— 经 login / login_ack 的权威快照重建状态； 不得在失步的连接上「跳过一帧继续解析」。
  • 首帧锚点：一条控制连接上的第一帧必须是 login（msg_type = 0x01）； 不满足必须关闭连接（CONTROL_ERROR）。
  • 有界扫描（推荐性，非规范性）：实现可以在关闭连接前做一次有界扫描辅助定位失步点； 其扫描范围、候选判据与扫描上限见下节「接收状态机」； 扫描结果仅用于诊断，不得用于恢复协议状态机。

接收状态机（规范性）

接收方必须以如下状态机驱动帧解析。状态机的内部实现方式自由 （同步阻塞读、异步回调、协程、事件循环均可）， 但其可观测行为必须满足下表与本节约束。

状态含义
SYNC帧边界可信；按 frame_len 正常解析帧
RESYNC已判定失步；仅用于有界扫描与诊断，不得回到 SYNC
CLOSED连接已关闭；承载的会话按 13 章处理（终结状态）

候选判据（用于 RESYNC 的有界扫描）

候选偏移 p 必须同时满足：

  1. p 起的 FRAME_HEADER_SIZE 字节构成合法帧头（三项校验通过）；
  2. p 起的第一帧完整可读（可用字节数 ≥ 该帧 frame_len）；
  3. 第一帧之后紧邻的第二帧的帧头也完整可读，且其三项校验通过（即「连续两帧自洽」）。

不满足第 3 条的候选不得采信 —— 消息体中偶然出现的 magic 几乎必然后跟非法帧头。 扫描上限 resync_max_scan = 64 KiB：实现可以取更小值，不得取更大值。

伪代码（说明性）

常量：MAGIC = 0x574E414C
      HEADER_SIZE = 16
      MAX_FRAME_LEN = 1 MiB
      RESYNC_MAX_SCAN = 64 KiB

SYNC（控制面接收循环）
  loop:
    若 缓冲区字节数 < HEADER_SIZE:
        继续读取（阻塞；超时 → CLOSED）
        continue

    h = 缓冲区[0 : HEADER_SIZE]
    magic, frame_len, crc, msg_type, flags, body_version, reserved = 解析(h)

    若 magic != MAGIC:                  → 失步(MAGIC_MISMATCH)
    若 crc32(h[0:8] ‖ h[12:16]) != crc: → 失步(HEADER_CRC_INVALID)
    若 frame_len < HEADER_SIZE 或 frame_len > MAX_FRAME_LEN:
                                        → 失步(FRAME_LEN_INVALID)

    body = 精确读取(frame_len − HEADER_SIZE)   # 读不满 → CLOSED（对端中断）
    交给消息处理器(msg_type, body)             # 非法消息只丢帧，不断连
    消费缓冲区前 frame_len 字节
    continue

失步(code):
    记录错误码 code
    若 实现提供有界扫描:  转 RESYNC          # 仅诊断
    否则:                  关闭连接 → CLOSED

RESYNC（仅诊断，不恢复协议状态机）
  从当前偏移逐字节前移，最多 RESYNC_MAX_SCAN 字节:
    若 候选满足「候选判据」:  记录候选偏移;  break
  关闭连接 → CLOSED
实现提示：缓冲区必须支持「读满一帧再消费」的滑动语义 —— 读帧体期间到达的字节必须留在缓冲区中供下一帧使用， 不得因一次 read 读到多帧而丢弃残余字节。
为何失步必须断连而非就地续解：被跳过的帧中可能含状态转移消息 （session_pause / session_abort / missing_chunks）。 一方跳过、一方不跳过时，双方对会话状态的认知已经分叉 —— 「看似同步、实则状态不一致」的连接比「已断开的连接」更危险： 断开的连接可由权威快照无歧义重建，分叉的连接不能。

TCP 特有约束

  • 控制连接必须启用 TCP_NODELAY（禁止 Nagle 合并）
  • 不得假设一帧一次 recv 到达 —— 必须按 frame_len 读满后再解析
  • 不得按换行或任何字节模式切分帧
  • 多帧可合并为一次 write，但不得延迟发送超过 50 ms
  • 不携带载荷级 CRC32：TCP 自带字节流校验和与重传；但帧头必须携带 header_crc32（用于帧同步，非载荷校验）
  • 心跳 ping 每 10 s；30 s 内无任何消息则关闭连接（TIMEOUT_HEARTBEAT）
  • 连接建立失败按 CONNECTION_FAILED 记录；连接被任一方关闭按 CONNECTION_CLOSED 记录（见 19 章）
