补充时序：摘要对帐 · 复核轮 · 主动投递 · 共享清单与拉取

控制面消息（发布方所在列） 对端动作 / 说明
下列时序按规范 24 章的箭头顺序渲染；箭头「→」表示消息由左列流向右列，「←」表示由右列流向左列。

摘要对帐时序（文件级失配时，恢复阶梯第 ① 级）

接收方（恒为请求方）
发送方（恒为应答方）
VERIFY 检测到文件级失配 → 状态退回 TRANSFERRING
保持源文件（size 必须与会话记录一致）
→ reconcile_request {ranges=[根区间]}（置 flags.bit0 根轮标志）
校验源文件 size 一致后，为每个区间计算 BLAKE3 摘要
用临时文件独立计算同区间摘要 → 逐区间比对
← reconcile_response {digests[]}（发送方侧的区间摘要）
→ reconcile_request {ranges=[左半, 右半]}（逐层二分，同轮同层）
← reconcile_response {digests[]}（每个子区间的摘要）
逐层下降直到 chunk_count = 1 → 定位可疑块 → 位图清零
（二等分规则由 (first_chunk, chunk_count) 唯一确定，双方无须协商）
→ missing_chunks {mode=report, chunks=可疑块}
按缺失列表定点补发（重传优先级高于新数据）
根区间摘要一致 → 双方内容相同 → 请求的 file_hash 有误 → session_abort(SOURCE_FILE_MISMATCH)，不再进入复核轮； 对帐后仍失配 → 进入复核轮（恢复阶梯第 ② 级）。

复核轮时序（文件级失配时，恢复阶梯第 ② 级）

接收方（发布方）
发送方
→ missing_chunks {mode=report, flags.bit1=复核轮, chunks=[]}
识别复核轮标志，准备全量重发
清空位图（临时文件保留）→ 重置顺序流与在途量基线
重新读取源文件，从 chunk_id = 0 起全量重发
乱序写盘并标记位图
← 全量数据流（UDP / TCP 数据面）
重新校验文件级 Blake3
对同一会话最多响应一次复核轮
复核轮至多一次；复核轮后仍失配才 session_abort(FILE_HASH_MISMATCH)（见 12 章）。

主动投递时序（Server → Client，无客户端请求）

Client（接收方）
Server（投递方）
（Client 未发起请求）
生成 session_id 与全套会话参数，创建会话（NEGOTIATING）
← delivery_offer {session_id, 全套会话参数, file_hash, file_name}
创建会话后等待接收方决策
接收方决策（策略 / 配额 / 用户）—— 可以拒绝
收到接受后，仍须等待该会话的 UDP_PROBE
→ delivery_response {result=success}（result=fail + code 即拒绝）
拒绝是正常协议结果；重复投递必须被幂等忽略
→ UDP PROBE（从接收方数据面 socket 发出）
← UDP PROBE_ACK（从 Server 数据面端口返回，打通 NAT 映射）
接收、落盘、提交
← UDP 数据面推送（等到 PROBE 之后才可发送）
→ download_complete
完成消息恒由接收方发布
Server 必须等到 PROBE 才可推送（20 章）；方向恒为 download， 完成消息恒由接收方发布；传输过程与普通下载完全一致。
