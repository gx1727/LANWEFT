路径一 · 断线重连

Client（发送方 / 接收方）
Server
TCP connect
接受连接
login {resume[]}
加载自己的位图
按快照覆盖本地状态
login_ack {sessions[] 权威快照}
各视角各自回到断线前状态（PAUSED 保持 PAUSED）
快照的权限边界（规范性）：Server 确定会话关联、协商参数和端口； 只有数据接收方的持久化位图决定块是否收到。两个计数不能表示稀疏位图， 不得用于重建或覆盖它。下载时 Server 必须回显 Client 提供的续传摘要； Client 保留本地 VERIFY / COMMIT 阶段。位图丢失且无法可靠重建时不得凭摘要续传。

路径二 · 暂停后恢复

Client
Server
session_pause
进入 PAUSED，停止发送数据包
resume_session {session_id, …}
回填权威续传位置
按快照重建状态
resume_ack {result, next_chunk_id, missing_count, udp_port}
双方回到 TRANSFERRING（该路径的前提就是解除暂停）
两条路径的语义一致：都返回接收方的权威续传位置与数据面端口，都使会话回到可传输状态。 恢复后各视角各自回到断线前状态（共享状态按快照，接收方本地校验与提交阶段按持久化记录）： PAUSED 保持 PAUSED（断线不解除显式暂停）， VERIFY / COMMIT 的接收侧回到原状态。
