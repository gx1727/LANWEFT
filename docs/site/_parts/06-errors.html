本章引用的错误码

下表列出 06 章正文引用、并必须经控制消息的错误码字段上线路的错误码（取值见 19 章）。 终止类消息用 reason 字段、结果可能成功也可能失败的消息用 code 字段； 双方必须按错误码分支判断，不得解析自由文本。

错误码出现位置（消息 · 字段）触发条件
ACL_DENY session_abort · reason Server 侧校验会话的 device_id 与控制连接绑定的身份不一致时， Server 必须以 session_abort（reason = ACL_DENY）拒绝该会话（见 21 章「访问控制」）。
CLIENT_ID_INVALID login_ack · code（result = fail） login 的 device_id 与认证凭据所绑定的身份不一致时， Server 必须以 login_ack（result = fail， code = CLIENT_ID_INVALID）拒绝并关闭连接。
FILE_HASH_MISMATCH session_abort · reason 复核轮之后文件级校验（Blake3）仍然失配时，接收方必须以 session_abort（reason = FILE_HASH_MISMATCH）终止会话（见 12 章）。
FILE_TOO_LARGE session_abort · reason 声明的文件大小超出该会话 chunk_size 可表示的上限时，Server 必须以 session_abort（reason = FILE_TOO_LARGE）拒绝， 且不得创建会话（见 09 章「文件大小上限」）。
PROTO_VERSION_UNSUPPORTED login_ack · code Client 不支持 Server 选定的 proto_version（Server 回填的 major 与 Client 声明的 major 不同）时， Client 必须关闭连接，并以 login_ack.code = PROTO_VERSION_UNSUPPORTED 报告（见 08 章「版本比较规则」）。
字段语义不重叠：result 字段（success / fail）用于「完成类」消息； code 字段用于「结果可能成功也可能失败」的消息；reason 字段用于「终止类」消息。 三者语义不重叠，实现不得混用。
