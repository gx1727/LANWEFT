消息类型编号（msg_type）

编号消息方向定长区变长区用途
0x01loginClient→Server8 Bdevice_id, token, resume[]连接握手、认证与恢复请求
0x02login_ackServer→Client10 Bcode, sessions[]握手结果与权威快照
0x03upload_startClient→Server28 Bfile_hash, file_name发起上传
0x04upload_acceptServer→Client32 Bfile_hash接受上传，返回会话参数
0x05download_startClient→Server28 Bfile_hash, file_name发起下载
0x06download_acceptServer→Client32 Bfile_hash接受下载，返回会话参数
0x07missing_chunks双向20 Bchunks缺失 chunk 报告 / 索要
0x08resume_sessionClient→Server20 B—恢复会话（显式暂停后的恢复）
0x09resume_ackServer→Client28 Bcode恢复确认与权威状态
0x0Aprogress_update双向24 B—传输进度更新（发布方恒为接收方）
0x0Budp_readyServer→Client12 B—UDP 可用性通知
0x0Cupload_completeServer→Client12 Bcode, file_hash, asset_id上传完成（接收方 Server 上报）
0x0Ddownload_completeClient→Server12 Bcode, file_hash下载完成（接收方 Client 上报）
0x0Esession_pause双向8 B—暂停会话
0x0Fsession_abort双向12 Breason, detail终止会话（发布方受限）
0x10asset_recallClient→Server4 Bfile_hash, asset_id请求撤回已上传的素材记录
0x11asset_recall_completeServer→Client4 Bfile_hash, asset_id, code, detail撤回处理结果回执
0x12ping双向8 B—心跳
0x13pong双向8 B—心跳应答
0x14reconcile_request双向
接收方发布		16 Branges[]摘要对帐请求（逐区间比对摘要）
0x15reconcile_response双向
发送方发布		16 Bdigests[]摘要对帐应答（各区间摘要）
0x16material_availableServer→Client8 Bentries[]共享清单变更通知（预置素材）
0x17material_listClient→Server16 B—查询共享清单（预置素材）
0x18material_list_ackServer→Client16 Bentries[]共享清单查询应答
0x19delivery_offerServer→Client48 Bfile_hash, file_name主动投递提议（携带全套会话参数）
0x1Adelivery_responseClient→Server12 Bcode, file_hash投递应答（接受 / 拒绝）
0x1Bcomplete_ack双向8 B—数据发送方确认已持久化接收方的完成回执
0x00, 0x1C–0xFF————保留，接收方必须忽略
帧长约束：frame_len ≥ 16（最小帧长即 16 字节帧头长度）、frame_len ≤ 1 MiB（max_frame_len）。 frame_len − 16 即消息体长度。 body_version 与协议版本 proto_version 相互独立，当前所有消息的 body_version 必须为 0。
定长区一旦发布即冻结：新增字段只能追加在扩展区，既有字段的偏移与大小不得变更；接收方必须忽略扩展区的全部内容。
