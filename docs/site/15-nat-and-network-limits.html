15 NAT 与网络限制

本章要点：协议面向同一局域网， 不提供任何穿透能力；跨公网 NAT / 蜂窝网络不支持， 二级路由条件支持。 协议假设 Client 可主动向 Server 发起 TCP / UDP， 因此建连与数据面探测都由 Client 发起； 实现上建议 Client 先发 UDP 以建立 NAT 映射， mDNS 可能失效，需支持手动配置地址。

可达性示意

Client（同一局域网）
Server
TCP connect（控制面）
监听控制端口
UDP PROBE（数据面）
PROBE_ACK（从会话数据面端口发出）
Server 以 PROBE 报文的源地址:端口作为该会话的对端数据面地址（见 07 章）
图示仅表达本章「协议假设」：双方处于同一局域网， Client 可主动向 Server 发起 TCP / UDP； Server 不主动向 Client 发起连接，也不做 NAT 穿透。 控制面与数据面的具体消息语义见 06、07 章。
与 04 章非目标一致：公网穿透与互联网规模传输不在本协议范围内（见 04 章）； 跨公网场景需要由实现层（而非协议层）另行解决。 本章不提供 NAT 打洞、端口预测或 relay 之类的穿透能力。

支持

  • 单一局域网
  • 二级路由（条件支持）
  • 跨公网 NAT/蜂窝网络不支持

假设

  • 同一局域网
  • Client 可主动向 Server 发起 TCP/UDP
  • 不提供穿透

建议

  • Client 先发 UDP 建 NAT 映射
  • mDNS 可能失效需手动配置
