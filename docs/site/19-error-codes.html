错误码上线路（规范性）

本章的错误码必须通过控制面消息上线路，字段映射如下：

消息 字段 语义
session_abort reason 终止原因，必填（str），取值来自本章
session_abort detail 可读补充说明（str），仅用于日志与 UI，不得用于逻辑判断
upload_complete code 失败时的错误码（符号名，str）；成功时为空串（长度 0）
download_complete code 失败时的错误码（符号名，str）；成功时为空串（长度 0）
asset_recall_complete code 未删除时的错误码（符号名，str）；成功删除时为空串（长度 0）
delivery_response code 拒绝诊断，可为 SERIALIZATION_ERROR；Server 转成终止原因时按 09 章映射
  • 发送方与接收方必须按错误码做分支判断，不得解析 detail 自由文本。
  • result 字段只表达「成功 / 失败」，不承载错误码； code / reason 字段必须是本章中定义过的标识符。
  • 未列在本章的错误码一律视为 UNKNOWN_ERROR。

建议错误码

SESSION

  • SESSION_NOT_FOUND：会话不存在或已终止
  • SESSION_ABORTED：会话被服务端终止
  • FILE_NOT_FOUND：请求的文件在 Server 上不存在或不可拉取 （含共享清单条目已被移除的情形）；Server 必须以 session_abort 拒绝
  • DELIVERY_DECLINED：接收方拒绝该次主动投递 （策略、配额或用户决定）；经 delivery_response.code 表达， Server 必须以 session_abort（reason = DELIVERY_DECLINED）终止会话
  • INVALID_STATE：当前状态不允许该操作
  • TOO_MANY_SESSIONS：单条控制连接上的并发会话数已达上限 （max_sessions_per_connection = 64，见 09 章）； Server 必须以 session_abort（reason = TOO_MANY_SESSIONS）拒绝该请求
  • PEER_DECLINED：接收方拒绝该次 C↔C 传输（策略、配额或用户决定）； Server 必须以 session_abort（reason = PEER_DECLINED）终止
  • PEER_UNREACHABLE：peer 直连探测失败，且未允许/无法使用中转
  • PEER_RELAY_UNAVAILABLE：直连不可用且中转不可用（无端点、容量不足或策略禁止）； Server 必须以 session_abort 终止并清理中转资源

TRANSPORT

  • UDP_UNAVAILABLE：UDP 探测失败
  • TCP_ERROR：TCP 数据面降级通道错误
  • BIND_FAILED：数据面端口绑定失败
  • CONNECTION_FAILED：控制通道连接失败
  • CONNECTION_CLOSED：控制连接已关闭（对端断开或超时）
  • NETWORK_ERROR：网络错误

INTEGRITY

  • CRC32_INVALID：包级校验失败（lv1；丢弃该包，不标记位图）
  • AUTH_TAG_INVALID：包级 keyed MAC / AEAD 校验失败（lv2/lv3；丢弃该包，不标记位图）
  • FILE_HASH_MISMATCH：文件级内容哈希不一致（必须按恢复阶梯处理： 摘要对帐 → 复核轮 → 仍失配才以 session_abort 终止会话，见 12 章）
  • SOURCE_FILE_MISMATCH：发送方的源文件与请求的 file_hash 不符 （摘要对帐的根区间摘要双方一致时判定，见 12 章）； 接收方必须以 session_abort 终止会话，不得再进入复核轮
  • INVALID_CHUNK：chunk_id 越界或非法
  • CHUNK_ALREADY_RECEIVED：重复 chunk（幂等丢弃）

AUTH

  • ACL_DENY：ACL 拒绝访问
  • CLIENT_ID_INVALID：client_id 非法
  • LOGIN_FAILED：登录认证失败
  • PROTO_VERSION_UNSUPPORTED：协议版本不受支持（见 06 章 login / login_ack）
  • SECURITY_LEVEL_UNSUPPORTED：Client 支持的最高安全等级 / 套件低于 Server 的 security_min_level 或 security_suites，无法协商（见 20 章）；Server 必须以 login_ack（fail）或对应拒绝消息终止，不得静默降级
  • FILE_TOO_LARGE：声明的文件大小超出 chunk_count / symbol_count 的 u32 上限， 或 chunk_size 不是 symbol_size 的整数倍 / S 超出 [1, 64] （见 09 章「文件大小上限与块参数校验」）；Server 必须以 session_abort （reason = FILE_TOO_LARGE）拒绝该请求，且不得创建会话

TIMEOUT

  • TIMEOUT_NO_ACTIVITY：长时间无活动导致超时（会话级，60 秒）
  • TIMEOUT_PROBE：UDP 探测超时
  • TIMEOUT_HEARTBEAT：控制连接心跳超时（30 秒无任何消息，见 06 章）
  • TRANSFER_STALLED：会话在 stall_timeout（10 秒）内没有任何缺失块到达且仍有缺失， 接收方终止（见 12 章「停滞检测与升级」）

STORAGE

  • DATABASE_ERROR：持久化失败（位图 / 会话元数据落盘）
  • STORAGE_FULL：接收方存储空间不足，无法容纳投递的文件； 经 delivery_response.code 表达
  • FILESYSTEM_ERROR：文件系统操作失败
  • SOURCE_READ_ERROR：发送方读取源文件失败；发送侧据此立即终止会话 （见 10 章「终止权」、12 章「停滞检测与升级」）

PROTOCOL

  • MAGIC_MISMATCH：帧头魔数不匹配，判定失步 （控制面与 TCP 数据面帧的 magic 均为 0x574E414C；见 06、07 章）
  • HEADER_CRC_INVALID：帧头 CRC32（CRC-32/ISO-HDLC）校验失败，判定失步 （见 06、07 章「帧头校验码」）
  • FRAME_LEN_INVALID：帧长越界（frame_len < 帧头长度或 > max_frame_len）， 判定失步；读取指针无法可信推进
  • INVALID_PACKET：数据包格式非法（长度不足、越界等）
  • SESSION_ID_MISMATCH：session_id 不匹配
  • SERIALIZATION_ERROR：控制帧解码失败（定长区长度不足、变长区越界、取值违反约束等）
  • PEER_TOKEN_INVALID：PROBE token 不匹配（C↔S 的 link_token 或 peer 的 transfer_token； 丢弃该 PROBE，不绑定端点）
  • CONTROL_ERROR：控制面错误
  • UNKNOWN_ERROR：未分类错误

终止类与过程类（规范性）

错误码按是否可作为会话终止原因分为两类：

类别 含义 可否作为 session_abort.reason / 完成消息 code
终止类 表示会话本身无法继续（会话被终止） 可以
过程类 表示传输过程中的局部异常；会话未必终止 不可以。可记录日志 / 指标；投递拒绝的诊断字段不是终止原因

终止类错误码清单（规范性）： SESSION_NOT_FOUND、SESSION_ABORTED、FILE_NOT_FOUND、DELIVERY_DECLINED、 INVALID_STATE、TOO_MANY_SESSIONS、FILE_HASH_MISMATCH、SOURCE_FILE_MISMATCH、 ACL_DENY、CLIENT_ID_INVALID、LOGIN_FAILED、PROTO_VERSION_UNSUPPORTED、 SECURITY_LEVEL_UNSUPPORTED、 FILE_TOO_LARGE、TIMEOUT_NO_ACTIVITY、TRANSFER_STALLED、DATABASE_ERROR、 STORAGE_FULL、FILESYSTEM_ERROR、SOURCE_READ_ERROR、PEER_DECLINED、 PEER_UNREACHABLE、PEER_RELAY_UNAVAILABLE。

其余错误码一律为过程类，即： UDP_UNAVAILABLE、TIMEOUT_PROBE、TCP_ERROR、BIND_FAILED、 CONNECTION_FAILED、CONNECTION_CLOSED、NETWORK_ERROR、 TIMEOUT_HEARTBEAT、CRC32_INVALID、AUTH_TAG_INVALID、INVALID_CHUNK、 CHUNK_ALREADY_RECEIVED、INVALID_PACKET、SESSION_ID_MISMATCH、 SERIALIZATION_ERROR、MAGIC_MISMATCH、HEADER_CRC_INVALID、 FRAME_LEN_INVALID、CONTROL_ERROR、PEER_TOKEN_INVALID、UNKNOWN_ERROR。

约束（规范性）：

  • 过程类错误码不得作为 session_abort.reason 或完成消息 code 上线路； 会话因过程类错误而结束时，必须以终止类错误码说明终止原因 （如传输层反复失败导致会话超时 → TIMEOUT_NO_ACTIVITY）。
  • 为何要区分（说明）：过程类错误描述的是传输链路的状态， 而 session_abort.reason 描述的是会话为何终止。 把 NETWORK_ERROR 当作终止原因上线路，会让对端误以为「文件有问题」， 实际只是「链路抖了一下，会话超时被清理了」。
  • 失步类错误（MAGIC_MISMATCH / HEADER_CRC_INVALID / FRAME_LEN_INVALID） 属过程类：它们导致连接关闭，会话进入 13 章「中断处理」， 不是会话的终止原因。

行为

  • 错误记录日志
  • INTEGRITY 错误包直接丢弃，且不得写入位图
  • SESSION 错误触发 session_abort（reason 填对应错误码）
  • CHUNK_ALREADY_RECEIVED 属幂等情形，静默丢弃即可
  • 同一错误不得导致状态机进入非法状态
  • 失步类错误（MAGIC_MISMATCH / HEADER_CRC_INVALID / FRAME_LEN_INVALID） 必须导致连接关闭（控制面连接或 TCP 数据面连接）， 不得在原连接上继续解析帧； 受影响会话必须按 13 章「断线重连」恢复
  • 过程类错误码必须记录到日志 / 指标，但不得作为终止原因上线路 （见「终止类与过程类」）
