LANWEFT 是什么

一句话：LANWEFT 是一套面向大文件同步的传输协议规范 —— 用 TCP 控制面承载会话、裁决与恢复，用 UDP 数据面承载高吞吐传输， 并提供 TCP 数据面作为兜底。

LANWEFT 不绑定具体实现、框架或应用。它规定的是线路格式、状态机、流控、可靠性、恢复、安全等级与错误码， 因此同一套协议可以由 PC、手机、NAS 或服务端各自实现并互通。 当前版本为 v0.3.0（Draft，设计阶段），线路格式仍在演进； 本页及站点各章是规范的可视化导读，发生冲突时以 docs/spec/ 源文为准。

解决什么问题（用途）

场景LANWEFT 提供的能力
局域网大文件同步 照片、视频、安装包、备份等大文件的高吞吐传输；控制与数据分离，避免逐包 ACK 与固定墙钟周期成为吞吐天花板。
PC ↔ 手机 / 多设备互传 上传、下载与 C↔C peer 三种方向；两端各自与 Server 保持既有登录，数据可直连，也可走 Server 的 R1 预选中转或 R2 会话内转发。
服务端素材分发 Server 维护素材与共享清单，支持主动投递、秒传与按需下载；接收方可以接受或拒绝投递。
弱网、中断与移动端 位图 + 缺失裁决、乱序写盘、断线重连、暂停恢复、停滞检测与复核轮；适配 Android / iOS 后台限制。
可信 LAN 之外的传输 会话级安全等级：lv1 CRC32（默认，可信 LAN）、lv2 BLAKE3 keyed MAC、lv3 AEAD；lv2/lv3 要求控制面 TLS，可用于不可信网络。

核心功能与特性

特性说明
控制面 / 数据面分离 TCP 长连接负责认证、会话、状态机与缺失裁决；UDP 负责数据搬运；UDP 不可用时回退 TCP 数据面，可靠性语义不变。
两级单位：chunk + symbol 逻辑块 chunk_size（默认 64800）用于寻址与位图；线缆/修复单位 symbol_size = 1200 字节；一个数据报承载 K 个 symbol，K 由传输层长度反推。
可变 K 与信任模式 K_nofrag 按路径 MTU 避免分片；显式开启信任模式后 K 可到 54（约 64KB 载荷），并按整报文丢失率自动回退。
无逐包 ACK 接收方维护位图并用 missing_chunks 精确上报缺失；窗口推进由 window_update 信用事件驱动，发送端只补缺失 symbol。
可中断、可恢复 断线重连走 login 恢复列表 + login_ack 权威快照；暂停恢复走 resume_session；空洞块永不重传，续传从第一个缺失 symbol 继续。
乱序写盘与原子提交 按 chunk_id × chunk_size + chunk_symbol × symbol_size 随机写临时文件，内存与文件大小解耦；校验通过后同一目录内 rename(2) 原子提交。
C↔C 直传与中转 两个 Client 复用各自与 Server 的登录；Server 做授权与控制中继，数据面可 direct，也可 R1（两段既有会话 + 临时素材）或 R2（同一 peer 会话内转发）。
完整性恢复阶梯 包级 trailer（lv1 CRC32 / lv2·lv3 tag）+ 文件级 Blake3；失配后依次尝试摘要对帐、复核轮，仍失败才终止。
分级数据面安全 会话级 lv1 / lv2 / lv3；PROBE 携带 probe_token 并绑定源端点；等级在会话内不可变，Server 可配置 security_min/default/max，禁止静默降级。

适用边界

适合

  • 可信局域网内的大文件高速同步（lv1 默认）
  • PC、手机、NAS 等多设备之间的上传 / 下载 / C↔C 互传
  • 需要断点续传、弱网恢复、移动端后台切换的传输
  • 需要服务端素材管理、主动投递或中转的部署
  • 需要密码学完整性或机密性的不可信网络（lv2 / lv3）

不是

  • 不是通用互联网 NAT 穿透方案：跨网可达性依赖端点或 Server 中转
  • 不是云端文件存储服务：Server 存储与配额由部署方定义
  • 不是 lv1 下的防伪方案：CRC32 只能发现损坏，不能阻止伪造
  • 不是已冻结的实现标准：v0.3.0 仍处于设计阶段，线格式可能继续演进
