12 可靠性模型（Reliability Model）

本章要点：可靠性由「裁决 + 完整性校验 + 重传 + 恢复 + 提交」五层构成。 裁决是唯一的推进依据（规范性）：接收方必须至少每 50 ms 下发一次 missing_chunks（mode=report），包括缺失列表为空的情况。 看门狗与保底轮询使用同一个 1000 ms 索要规则。控制连接断开不得直接置为 ABORTED，只有 60 秒会话活动超时才终止会话。

分层保障

可靠性分层（自下而上）
① 缺失裁决与位图 · 控制面统计缺失并下发 missing_chunks(mode=report)；接收端乱序写盘与位图
② 完整性校验 · crc32 包级 + 文件级 Blake3
③ 重传 · UDP 不即时重传；聚合缺失后统一下发；重传优先级高于新数据
④ 中断与恢复 · 不回滚已写入；恢复后加载位图并补传缺失
⑤ 完成与提交 · bitmap 全真 → 校验 hash → 原子重命名 → 发布完成消息
裁决是唯一的推进依据（规范性）：接收方必须至少每 50 ms 下发一次 missing_chunks（mode=report），包括缺失列表为空的情况； 发送方据此推进窗口。详见 11 章「窗口推进判据」。

保底轮询（Keep-Alive Polling）

  • Client 发送完全部数据后，若 Server 持续返回 missing_chunks（mode=report） 且 chunks 为空（缺失列表为空），但始终未下发 upload_complete， Client 进入保底轮询状态。
  • 保底轮询使用 11 章判据第 4 条的同一个 1000 ms 索要规则： Client 必须按该周期发布 missing_chunks（mode=request） 持续索要缺失列表，直至收到 upload_complete 或触发超时。
  • 目的：防止对端状态机卡死导致的会话悬挂。

连接断开的语义（规范性）

控制连接断开时，该连接承载的全部会话必须视为中断（可恢复）， 不得直接置为 ABORTED。
  • 断连不回滚已写入的数据，位图与临时文件必须保留。
  • Client 重连后通过 login 的恢复列表恢复（见 13 章）。
  • 只有会话活动超时（60 秒，见 09 章）才把会话置为 ABORTED 并清理资源。

看门狗（Watchdog）

  • 看门狗的职责与 11 章判据第 4 条的索要规则完全一致： 发送方每 1000 ms 至少索要一次裁决，直到收到 mode=report 为止。
  • 重复的 mode=request 是幂等的，与幂等要求兼容 （见 06 章「未识别消息必须忽略，保持幂等性」）。

完整性校验

层级 / 情形规范要求
包级 每个 UDP 包尾部携带 CRC32（覆盖 16 字节头 + payload），校验失败直接丢弃，不得写入位图； 该块随即成为「未收到」，按定点补发处理 —— 单次校验失败的代价是一个块，不是整个文件
文件级 传输完成后，接收方计算全文件 Blake3 哈希，与请求中的 file_hash 比对 （file_hash 为 32 字节原始 Blake3 摘要，hash32 类型，非十六进制串）； 一致才进入 COMMIT 并发布完成消息（上传方向 upload_complete， 下载方向 download_complete）
恢复阶梯 文件级失配后按 ① 摘要对帐 → ② 复核轮 → ③ 中止 逐级恢复，每一级至多一次：
① 摘要对帐：逐区间比对摘要，零内容流量地定位差异区间 → 清零可疑块位图 → 复用既有缺失裁决定点补发；
② 复核轮：重新读取源文件并全量重发；
③ 中止：session_abort(FILE_HASH_MISMATCH)。
对帐的根区间摘要一致时，判定请求的 file_hash 与源文件不符 → SOURCE_FILE_MISMATCH，不再进入复核轮。
文件级校验失败 → 复核轮 接收方不得立即终止会话，必须进入复核轮：
① 清空位图（临时文件保留）；② 发布带复核轮标志 （missing_chunks.flags.bit1 = 1）的裁决，chunks 为空列表、 missing_count = chunk_count；③ 发送方必须重新读取源文件、 从 chunk_id = 0 起全量重发；④ 重新校验文件级 Blake3。
复核轮至多一次（计数必须随位图持久化）。
复核轮后仍失配 接收方必须发布 session_abort（reason = FILE_HASH_MISMATCH） 终止会话。此时源文件确实不可读或已被改动。
这是接收侧唯一有权发起的终止（见 10 章「终止权」）；其余终止原因一律由 Server 发起。
秒传路径 跳过数据传输时没有位图，完成条件为「既有文件校验通过并原子提交」（见 10 章「秒传路径」）
本章与其它章的关系：窗口推进与索要判据见 11 章；会话状态与终止权见 10 章； 断线恢复见 13 章；会话超时阈值见 09 章；包级校验与包头布局见 07 章与 08 章。 常见实现陷阱：把 50 ms 的裁决周期当成「有缺失才下发」，或把 missing_count 误当作本批 chunks 的长度；以及把文件级失配直接实现成终止 —— 那会让 100 GiB 文件因一次未被检出的位翻转（CRC32 漏检概率约 2.1%）而全部作废。
