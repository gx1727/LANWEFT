00 概览（Overview）

本章要点：LANWEFT 是面向可信局域网的混合文件同步协议，通过「控制面 TCP + 数据面 UDP」双通道协作， 在保证高吞吐的同时实现可中断、可恢复、可裁决的文件同步能力。本章规定控制面载荷的 小端二进制定长布局与基础类型，给出发送侧 / 接收侧视角定义、文档约定与规范性用语的强度， 并声明协议版本为 v0.3.0（规范草案修订中，尚未冻结）。

核心特性

  • 局域网内大文件（照片 / 视频）高效同步
  • 不中断可恢复、乱序写盘、内存与文件大小解耦
  • 控制与数据分离，可靠性由控制面裁决
  • 控制面：TCP 长连接（二进制帧格式 + 权威快照重同步）；数据面：UDP；位图进度；会话恢复；NAT 探测

表示形式（规范性）

控制面载荷为小端二进制定长布局。控制帧与消息体的结构如下（详见 06 章）：

控制帧 = frame_len + 8 字节定长帧头 + 消息体
u32 frame_len
u8 msg_type
u8 flags
u8 body_version
u8 reserved
消息体 body
定长区（表格式偏移 / 大小）
变长区（顺序固定）
长度前缀 frame_len 定长帧头字段 版本字段 定长区 变长区
消息体 = 定长区（表格式偏移 / 大小）+ 变长区（顺序固定）；本图仅示意结构，字段含义见 06 章。

基础类型

类型 表示 说明
u8 / u16 / u32 / u64 小端 无符号整数，一律使用小端序
bool u8 取值 0 / 1
str u16 长度 + UTF-8 长度 0 表示无值
hash32 32 bytes 32 字节原始 Blake3 摘要
数据面数据包的格式见 08 章，本规范不在此重复定义。

角色与视角

视角 定义 上传方向 下载方向
发送侧 发送数据的一方 Client Server
接收侧 持有位图与临时文件的一方 Server Client
  • 完成消息一律由接收方发布
  • 缺失报告一律由接收方发起
  • Server 拥有最终的会话终止权
详见 10 章「视角定义」。

文档约定（规范性）

文档性质

本文件是协议设计说明书。正文只包含协议本身：规范要求、推荐做法与设计理由。

  • 不记录修订过程（哪一版改了什么）—— 修订历史必须记入 26 章「修订记录」。
  • 不描述具体实现（编程语言、库、私有 API、源码路径）—— 实现细节不构成协议的一部分（见 25 章）。
  • 不做版本对比 —— 正文陈述的是当前协议， 不得使用「改由 / 取代 / 不再」等与前一版本对比的措辞， 不得引用协议中已不存在的概念（见 25 章）。

规范性用语的强度

用语 含义
必须 / 不得 强制要求，违反即为实现错误
应当 强制要求（允许有充分理由的例外，例外应当有记录）
建议 / 推荐 强烈建议，偏离时应当说明理由
可以 允许但不要求
  • 规范性要求必须写在正文，不得藏在引用块中。
  • 非规范性内容（实现建议、背景说明）必须显式标注为 「非规范性（Non-Normative）」或「推荐性」，见 25 章。
  • 设计理由（为什么这样规定）应当以「说明」小节或正文段落呈现， 与规范性要求明确区分。
