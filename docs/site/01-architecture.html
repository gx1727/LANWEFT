01 架构（Architecture）

本章要点：协议分层为应用层 → 控制层（TCP） → 数据层（UDP/TCP） → 网络层（LAN）。 控制面负责连接握手与认证、会话建立 / 协商、缺失统计与重传裁决、UDP 可用性探测、完成与终止、进度通知， 以及由连接存续直接表达的心跳与在线状态；数据面只负责 Chunk 传输、CRC32 包级校验与随机写盘位图。 原则：状态机仅由控制面推进，数据面只更新位图、不直接触发状态转移； Server 拥有一般终止权（会话参数、状态、超时的裁决由 Server 做出）， 非 Server 的接收方可因完整性或持久化失败终止，允许的原因与条件以 10 章「终止权」为准。

分层架构

应用层 → 控制层（TCP） → 数据层（UDP/TCP） → 网络层（LAN）。

各层职责

控制面

  • 连接握手与认证
  • 会话建立/协商
  • 缺失统计与重传裁决
  • UDP 可用性探测
  • 完成与终止
  • 进度通知
  • 心跳与在线状态（由连接存续直接表达，见 06 章）

数据面

  • Chunk 传输
  • CRC32 包级校验（覆盖头部与载荷）
  • 随机写盘与位图

角色与视角

协议区分两个角色视角（详见 10 章「视角定义」）：

视角 定义 上传方向 下载方向 peer 方向
发送侧 发送数据的一方 Client Server sender_device_id
接收侧 持有位图与临时文件的一方 Server Client receiver_device_id
  • 完成消息一律由接收方发布：upload_complete 由 Server 发布， download_complete 由 Client 发布，peer_complete 由 receiver_device_id 发布 （经 Server 中继）。
  • 缺失报告一律由接收方发起：missing_chunks（mode=report）由接收方下发， 发送方据此补发。

原则

  • 状态机仅由控制面推进；数据面只更新位图，不直接触发状态转移
  • Server 拥有一般终止权：会话参数、状态、超时的裁决由 Server 做出
  • 非 Server 的接收方可因完整性或持久化失败终止，允许的原因与条件以 10 章「终止权」为准。
  • 控制面拥有最终裁决权；数据面仅负责搬运与落盘
注意：数据面收到重复或乱序的数据包时只能更新位图， 不得直接触发状态转移；缺失的裁决与重传请求一律经由控制面完成。
