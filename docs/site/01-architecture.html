01 系统架构（Architecture）

本章要点：LANWEFT 采用应用层 → 控制层（TCP）→ 数据层（UDP/TCP）→ 网络层（LAN）的分层结构。 控制面负责握手认证、会话协商、缺失统计与重传裁决、UDP 可用性探测、完成与终止、进度通知以及心跳与在线状态； 数据面只负责 Chunk 传输、CRC32 校验与随机写盘位图。状态机仅由控制面推进， Server 为最终裁决者——任何进入 ABORTED 的转换只能由 Server 发起。

各层职责

控制面

  • 连接握手与认证
  • 会话建立 / 协商
  • 缺失统计与重传裁决
  • UDP 可用性探测
  • 完成与终止
  • 进度通知
  • 心跳与在线状态（由连接存续直接表达，见 06 章）

数据面

  • Chunk 传输
  • CRC32 校验
  • 随机写盘与位图
控制面细节见 06 章「控制面（TCP）」； 数据面细节见 08 章「数据包结构」。

角色与视角

协议区分两个角色视角（详见 10 章「视角定义」）：

视角 定义 上传方向 下载方向
发送侧 发送数据的一方 Client Server
接收侧 持有位图与临时文件的一方 Server Client
  • 完成消息一律由接收方发布：upload_complete 由 Server 发布， download_complete 由 Client 发布。
  • 缺失报告一律由接收方发起：missing_chunks（mode=report）由接收方下发， 发送方据此补发。

原则

  • 状态机仅由控制面推进；数据面只更新位图，不直接触发状态转移。
  • Server 为最终裁决者：任何进入 ABORTED 的转换只能由 Server 发起。
  • 控制面拥有最终裁决权；数据面仅负责搬运与落盘。
注意：数据面收到重复或乱序的数据包时只能更新位图， 不得直接触发状态转移；缺失的裁决与重传请求一律经由控制面完成。
