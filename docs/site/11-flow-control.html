11 流控（Flow Control）

本章要点：window 是在途上限，由 Server 下发； 无逐包 ACK，发送方推进窗口的唯一依据是接收方周期性下发的 missing_chunks（mode=report）裁决 —— 空列表裁决也必须下发。

窗口与吞吐的关系

window在途数据量吞吐上限

稳态吞吐上限 ≈ window × chunk_size / 裁决周期；以 chunk_size = 1200、裁决周期 50 ms 计。 Server 应当依据目标链路速率与 chunk_size 选取 window，1 Gbps 局域网的推荐取值为 4096。

发送节奏

  • 发送方必须按批次发送：连续发送 burst_size 个 chunk（批内不逐包停顿），批间隔 batch_gap_us
  • burst_size 初值 = Server 下发的 window；batch_gap_us 初值 = 2000 µs
  • burst_size 必须 ≤ window
  • 发送方必须持续推进批次，直到 chunk_count 全部发出；唯一的停顿条件是在途量触及 window 上限

窗口推进判据（规范性）

#规则
1发送方持续发送新 chunk，直到 chunk_count 全部发出
2发送方必须以最近一次 missing_chunks（mode=report）裁决中报告的缺失列表作为重传依据，重传优先级高于新数据
3发送方必须维护在途量估计，不得超过 window；达到上限时必须暂停发送新数据（重传不受此限），直至收到下一次裁决后重新计算。一旦开始发送一个批次，必须发完该批次。
4发送方在「等待裁决」状态下必须保持 1000 ms 周期：距上次收到 mode=report 超过 1000 ms 时，必须发布 missing_chunks（mode=request）主动索要；每收到一条 mode=report（无论是否为空）即重置该计时器
5接收方必须至少每 50 ms 下发一次 missing_chunks（mode=report），即使缺失列表为空也必须下发；收到 mode=request 时必须在 50 ms 内以 mode=report 应答
空列表裁决是必需的（规范性）：若接收方只在「有缺失」时才下发，发送方将在窗口填满后 永远等不到裁决，协议死锁。因此周期性下发空列表裁决是规范性要求，而非优化建议。

在途量估算与恢复基线

情形处理
missing_count 已知R = chunk_count − missing_count；S 为已发不同 chunk_id 数（重传不重复计数）；在途量 = max(0, S − R)
missing_count 未知（存在标志位为 0）R 无法求出 → 保守退化：把裁决报告的缺失块全部视为仍未到达，在途量不得超过 window − len(chunks)；chunks 为空列表时退化为 window
恢复后的基线会话重建后，发送方必须把 S 的基线重置为 chunk_count − 权威快照的 missing_count（即 R）；基线重置后 S = R，在途量为 0
恢复后（连接重建）发送方必须丢弃恢复前的在途量估计，在收到权威快照之前不得发送新数据

动态流控：AIMD（推荐性）

  • 本节描述发送端本地策略，不属于互操作要求：两端实现可以采用完全不同的策略，协议行为必须保持一致
  • 发送侧依据对端周期性下发的 progress_update 估算链路状况，调节 burst_size 与 batch_gap_us；两个方向同等适用
  • 丢包率估算：loss_rate = 1.0 − (delta_received / delta_sent)；估算必须基于滑动窗口内累计值（窗口长度建议为最近 20 个 tick）；样本量不足（delta_sent < 16）时不得据此调整；delta_sent = 0 时不得触发除法
  • batch_gap_us 范围 [0, 100000] µs；burst_size 范围 [min(64, window), window]
  • 每次调整应当加入随机抖动（jitter），避免多个 Client 同步震荡
条件动作
拥塞（loss_rate > 5%）batch_gap_us = min(max(batch_gap_us × 1.5, 200), 100000)
burst_size = max(burst_size × 0.7, min(64, window))
通畅（loss_rate < 1%）batch_gap_us = max(batch_gap_us − 10, 0)
burst_size = min(burst_size + 2, window)
中间区间（1% ≤ loss_rate ≤ 5%）保持不变
前提条件：AIMD 只作用于发送节奏，不改变协议语义；数据面不做拥塞控制， AIMD 属于客户端策略而非协议层机制。
