18 位图与块图（Bitmap & Chunk Map）

本章要点：接收方的位图必须提供判定 / 枚举 / 计数 / 持久化四项能力； 位图的内部组织方式（位图字长、原子类型、内存布局）由实现决定，不构成互操作要求， 但位图必须支持按 chunk_id 升序枚举。 单条 missing_chunks 载荷中的 chunk 条目不得超过 4096 条， 接收方必须按位图顺序（chunk_id 升序）分批下发缺失列表。

本例中按 chunk_id 升序枚举的第一个缺失块 = chunk_id 5， 即缺失列表的起点，也就是续传的起点： 缺失列表必须按升序分批下发，发送方据此补发缺失块（见本章「缺失列表的下发上限」）。
空洞位格（chunk_id ≥ chunk_count）不属于文件内容，不参与缺失计数。
幂等性：重复标记同一 chunk_id 必须是幂等的 （第二次标记不改变状态）；因此重放保护在 session_id 校验与越界拒收之外， 由位图幂等性兜底（重复 chunk 静默丢弃，见 20 章）。

位图的协议能力（规范性）

  • 位图的内部组织方式（位图字长、原子类型、内存布局）由实现决定，不构成互操作要求。
  • 位图必须支持按 chunk_id 升序枚举 —— 缺失列表的分批下发依赖升序 （见本章「缺失列表的下发上限」）。

块图（Chunk Map）数据结构

missing_chunks 载荷布局（缺失块列表 / 块图的对外表达）
mode (enum8)
0 = report / 1 = request
flags (u8)
bit0 = missing_count 有效
missing_count (u32)
尚未收到的 chunk 精确总数
chunks (chunk_list)
u32 条数 + u32 chunk_id 数组
mode flags missing_count chunks
字段 类型 语义与约束
mode enum8 0 = report（接收方下发缺失报告）、1 = request（发送方索要缺失列表）
chunks chunk_list u32 条数 + u32 chunk_id 数组；二进制下为升序排列； 单条载荷中的 chunk 条目不得超过 4096 条
missing_count u32 位图中尚未收到的 chunk 精确总数； 对端未携带该字段时（flags.bit0 = 0）该字段必须为 0
flags u8 bit0 = missing_count 有效；未携带该字段时必须置 0
  • 载荷中的 missing_count 字段给出位图中尚未收到的 chunk 精确总数， 用于发送方判断是否还有后续批次并推算在途量（见 11 章判据第 3 条）。
  • 对端未携带该字段时（flags.bit0 = 0，此时该字段必须为 0）， 发送方必须按「可能还有后续批次」处理， 并采用 11 章判据第 3 条规定的保守退化策略。

刷盘策略（推荐性）

  • 建议每 1s 或每 100 chunk 刷盘一次。
  • 避免每 chunk 同步刷盘。

缺失计算优化

  • 以 u64 为单位批量跳过全 1 的块。
  • 只有当 word != u64::MAX 时才逐位检查。
位图的内部组织方式由实现决定，不构成互操作要求； 上述刷盘与扫描策略属于推荐性内容，协议只约束位图的对外语义 （判定 / 升序枚举 / 计数 / 持久化）。

缺失列表的下发上限（规范性）

  • 单条 missing_chunks 载荷中的 chunk 条目不得超过 4096 条 （受控制通道 max_frame_len = 1 MiB 的约束，见 06 章「帧格式」）。 二进制下 chunks 为 chunk_list（u32 条数 + u32 chunk_id 数组）， 4096 条 = 4096 × 4 = 16 KiB，仍远小于 max_frame_len = 1 MiB。
  • 接收方必须按位图顺序（chunk_id 升序）分批下发缺失列表： 一批被补齐后，下一批在随后的裁决周期中下发。
  • 载荷中的 missing_count 字段给出位图中尚未收到的 chunk 精确总数， 用于发送方判断是否还有后续批次并推算在途量（见 11 章判据第 3 条）； 对端未携带该字段时（flags.bit0 = 0，此时该字段必须为 0）， 发送方必须按「可能还有后续批次」处理， 并采用 11 章判据第 3 条规定的保守退化策略。
  • 缺口规模估算：100 GB 文件、chunk_size = 1200 约 8.9×10⁷ 块， 即使缺失 1% 也达 8.9×10⁵ 条，必须依赖上述分批机制。
限制项 取值 依据
单条 missing_chunks 的 chunk 条目上限 4096 规范性：不得超过 4096 条
4096 条的二进制大小 16 KiB 4096 × 4 字节（u32 chunk_id 数组）
控制通道 max_frame_len 1 MiB 见 06 章「帧格式」，16 KiB 远小于该上限
下发顺序 chunk_id 升序 接收方必须按位图顺序分批下发
常见实现陷阱：把缺失列表一次性塞进单条载荷（超过 4096 条）； 下发顺序不按 chunk_id 升序；用「缺口条数」而不是位图的精确总数填写 missing_count； 在对端未携带 missing_count 时仍按「没有后续批次」处理。
