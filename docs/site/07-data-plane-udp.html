07 数据面（UDP / TCP Fallback）

本章要点：数据面以 UDP 为默认传输，原则是 无连接、无逐包 ACK、允许丢包与乱序，并以 crc32 做包级校验、 并以 crc32 做包级完整性校验； UDP 不可用时回退到数据面 TCP 通道（与 06 章的控制面 TCP 长连接完全无关）。 数据面不得改变会话状态，只更新接收侧位图。

UDP 原则

  • 无连接、无逐包 ACK、允许丢包与乱序
  • payload_len ≤ chunk_size（建议 chunk_size ≤ 1400，避免 IP 分片）
  • crc32 包级校验（覆盖头部与载荷）

发送端与接收端

发送端

  • 按批次发送：连续发送 burst_size 个 chunk，批间隔 batch_gap_us （初值 2000 µs；burst_size 初值 = window）。详见 11 章「发送节奏」。
  • 批内不逐包停顿；间隔施加在批与批之间，而非包与包之间。
  • 仅对 missing_chunks（mode=report）报告的缺失块重传， 重传优先级高于新数据
  • 数据面不得改变会话状态，只能更新接收侧位图（见 10 章「推进规则」）

接收端

  • 校验头与 crc32
  • 随机写盘
  • 标记位图
  • 不直接推进状态机（位图变化只是接收侧状态推进的输入）

探测三步：PROBE → PROBE_ACK → 控制通道下发 udp_ready。

PROBE 数据包

  • flags.bit3 = 1
  • payload 为 session_id（u64）的 8 字节小端编码（payload_len = 8）
  • payload_len == 4

PROBE_ACK 数据包

  • flags.bit3 = 1
  • payload 为 session_id + 1 字节状态码（0=成功，1=失败）， 共 5 字节
  • payload_len == 5
判别规则（规范性）：PROBE 与 PROBE_ACK 共用 flags.bit3， 接收方必须以 payload_len 区分：payload_len == 4 为 PROBE， payload_len == 5 为 PROBE_ACK。其余长度必须按 INVALID_PACKET 丢弃。

端口与地址绑定（规范性）

  • Server 的数据面 socket 必须绑定 accept 消息中下发的 udp_port。
  • Server 必须以 PROBE 报文的源地址:端口作为该会话的对端数据面地址； Server 不得向未经 PROBE 确认的地址发送数据面数据包（见 20 章）。
  • Server 返回的 PROBE_ACK 必须从该会话的数据面端口发出， 以保证客户端的 NAT 映射命中。

接收方 socket 生命周期（规范性）

要点要求
两个方向都必须有 「接收方」= 持有位图与临时文件的一方（上传方向为 Server，下载方向为 Client）。 下载方向更是强制的：Server 不得向未经 PROBE 确认的地址发送数据（见 20 章）， 因此接收方必须主动发出 PROBE 告知自己的数据面地址
打开时机 接收方必须在发出 PROBE（或建立 TCP 数据面连接）之前打开 socket； 否则 PROBE 的源端口与后续接收端口不一致，对端会把数据发往错误地址
端口来源 接收方不必绑定固定端口 —— 通常用临时端口， 由对端从 PROBE 的源地址:端口学到；多个会话可以共用同一个 socket
结束判据 数据面通道的结束必须由控制面状态表达（会话进入 COMPLETED / ABORTED）； 不得仅凭「位图已全真」就关闭 socket —— 那时对端可能仍有在途数据
关闭前 必须已发布完成消息；若完成消息未送达， 必须在会话进入终态前继续应答 missing_chunks（mode=request）

超时

  • Client 等待 PROBE_ACK 超时（建议 2 s）则判定 UDP 不可用
  • 回退到 TCP

TCP 降级

  • UDP 不可用或异常时启用
  • 保持 chunk 与 bitmap 语义
  • TCP 通道的线路格式见 07 章「TCP 数据面线路格式」： 帧边界、绑定与权限校验均必须与 UDP 通道语义一致
  • TCP 端口由 accept 消息的 tcp_port 字段下发；tcp_port = 0 表示不支持 TCP 降级， 此时探测失败即判定传输不可用
