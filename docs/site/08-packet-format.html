错误处理规范 (Error Handling)

  • 所有多字节字段必须使用 小端序 (Little-Endian)
  • CRC32 校验失败的包 必须丢弃 (MUST discard)
  • Session ID 不匹配的包 必须丢弃 (MUST discard)
  • Payload Length 非法的包 必须丢弃 (MUST discard)
  • payload_len 越界（> 1400 或 > 本会话协商的 chunk_size）→ 判为 INVALID_PACKET，丢弃且不得写入位图
  • 最后一个 chunk 的 payload_len 必须等于 size − chunk_id × chunk_size；不等即判为 INVALID_PACKET，丢弃
  • chunk_id ≥ chunk_count 的包 必须丢弃 (MUST discard)
  • 该 chunk_id 已收到（重复包）→ 幂等丢弃，不重复写盘（CHUNK_ALREADY_RECEIVED）

CRC32 变体 (CRC Variant)

  • 必须使用 CRC-32/ISO-HDLC (zlib crc32)
  • 多项式 0x04C11DB7 (反射 0xEDB88320)
  • 初值与末尾异或均为 0xFFFFFFFF，输入输出均反射
  • 校验值: "123456789" → 0xCBF43926
  • 覆盖区间: 16 字节头 + payload，不含尾部 CRC 字段本身

包级校验与块级补救

  • 接收方必须在写盘前校验 crc32，失败即丢弃且不得写入位图
  • 该块保持「未收到」→ 缺失裁决精确报告 → 发送方只补发该块
  • 单次校验失败的代价是一个块，与文件大小无关

版本协商与协议版本（规范性）

不兼容扩展通过控制通道的协议版本协商达成：控制面 login 携带 proto_version，Server 在 login_ack 中回填选定的版本； Client 不支持该版本时必须关闭连接（见 06 章）。

环节规范要求
编码 版本号在控制面上编码为三个 u8（major / minor / patch，见 06 章 login）， 按 major → minor → patch 逐段数值比较。
Client 声明 Client 声明其最高支持的版本（login 的 proto_major / proto_minor / proto_patch）。
Server 回填 Server 应当在 login_ack 中回填两者都支持的最高版本。
major 必须相同 Server 回填的版本其 major 必须等于 Client 声明的 major —— major 不同即不兼容：Client 必须关闭连接， 并以 login_ack.code = PROTO_VERSION_UNSUPPORTED 报告。
minor / patch 差异 major 相同、minor 或 patch 不同即视为兼容：新增字段一律可选，接收方必须忽略不认识的字段。
0.x 例外（规范性） 本规范处于 0.x 阶段，minor 变更可能是不兼容的 —— 例如 v0.3.0 相对 v0.2 的控制面即不兼容（传输层、帧格式、消息集均已改变）。 因此 minor 不同不得作为「可互通」的充分依据； 实现必须以 06 章的消息集为准判断实际兼容性（版本策略见 26 章）。
数据面格式绑定 数据包格式的任何不兼容变更必须伴随 proto_major 的提升； Server 不得向仅支持旧 major 的对端建立使用新格式的数据面会话。
注意：proto_version（协议版本）与 06 章帧头中的 body_version（消息体布局版本）相互独立； 版本差异一律由二者表达，magic 不得随协议版本变更。
头部长度 HEADER_SIZE = 8 + 4 + 2 + 2 = 16 字节，CRC_SIZE = 4 字节； payload_len ≤ 1400 且 payload_len ≤ 协商 chunk_size，推荐 chunk_size = 1200 字节。 以 1200 字节块长计，线上包长 = 16 + 1200 + 4 = 1220 字节，叠加 IP/UDP 28 字节后仍小于 1500 字节 MTU。
为什么单次校验失败 ≠ 整文件重传：本协议不采用逐包 ACK，而采用「位图 + 缺失裁决」。 任何一次校验失败都只是让对应的那一个块保持「未收到」； 该块会在下一次裁决（≤ 50 ms）中被精确报告，发送方按缺失列表只补发该块。 只有文件级校验失配才需要整文件重传（复核轮，见 12 章）。
CRC32 的已知代价：只有 32 位，未检出概率约 2⁻³² —— 100 GiB 文件约 2.1%、1 TiB 约 20.8%。 漏检的损坏会撑到文件级校验并触发一次复核轮（整文件重传）。 规范将其记为已知代价，修复手段是复核轮，而非更重的逐块摘要机制。
