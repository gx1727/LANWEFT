头部 16 字节按字节成对划分，刻度与字段行一一对齐： session_id 占 4 格（0–7）、chunk_id 占 2 格（8–11）、 payload_len / flags 各占 1 格（12–13 / 14–15）。

错误处理规范 (Error Handling)

  • 所有多字节字段必须使用 小端序 (Little-Endian)
  • CRC32 校验失败的包 必须丢弃 (MUST discard)
  • chunk_digest 校验失败的包 必须丢弃且不得标记位图 (MUST discard)，该块按定点补发处理（仅在携带摘要的包上可能发生）
  • Session ID 不匹配的包 必须丢弃 (MUST discard)
  • Payload Length 非法的包 必须丢弃 (MUST discard)
  • chunk_id ≥ chunk_count 的包 必须丢弃 (MUST discard)

CRC32 变体 (CRC Variant)

  • 必须使用 CRC-32/ISO-HDLC (zlib crc32)
  • 多项式 0x04C11DB7 (反射 0xEDB88320)
  • 初值与末尾异或均为 0xFFFFFFFF，输入输出均反射
  • 校验值: "123456789" → 0xCBF43926
  • 覆盖区间条件式：携带 chunk_digest 时为 16 字节头 + 8 字节摘要（24 字节）；不携带时为 16 字节头 + payload；均不含尾部 CRC 字段本身
  • 载荷由 chunk_digest 保护，不被 CRC32 重复计算（省约 20% CPU/块）

逐块摘要 (chunk_digest)

  • 可选：会话参数 chunk_digest（0 = 关闭 / 1 = 启用，规范默认值 1）决定是否携带
  • 算法 BLAKE3，输出长度 8 字节（XOF），仅覆盖 payload
  • 发送方必须对实际发出的字节计算摘要
  • 接收方校验顺序：先 crc32（仅 24 字节）→ 再摘要 → 再写盘
  • 摘要失配则丢弃该包并请求该块（定点补发，不进复核轮）
代价与边界：摘要约 17% 单核 @ 1 Gbps（每端）。 未检出概率 2⁻³² → 2⁻⁶⁴，对应 100 GiB 文件「走一次复核轮（整文件重传）」的概率由 约 2.1% 降到可忽略；但仅从省带宽看是净亏损 （约 143 CPU-秒/端 vs 约 18 秒额外传输） ——摘要的主要价值在写盘后回读校验。 Server 可在「文件小 / 存储可靠 / 不启用回读校验」时关闭它；关闭后协议行为不变， 只是载荷完整性由 CRC32 单独承担。
头部长度 HEADER_SIZE = 8 + 4 + 2 + 2 = 16 字节，DIGEST_SIZE = 8 字节，CRC_SIZE = 4 字节； payload_len ≤ 1400 且 payload_len ≤ 协商 chunk_size，推荐 chunk_size = 1200 字节。 以 1200 字节块长计：启用摘要时线上包长 = 16 + 1200 + 8 + 4 = 1228 字节， 关闭时 = 16 + 1200 + 4 = 1220 字节；叠加 IP/UDP 28 字节后均小于 1500 字节 MTU。

crc32 与 chunk_digest 的分工

维度crc32chunk_digest
覆盖对象 整个包：16 字节头 + payload + 摘要本身 仅块载荷（不含包头、不含 crc32）
校验层次 逐跳：只在收到时验证一次，此后不可重验 端到端：可对已落盘的内容随时重新验证（回读校验）
强度 32 位 · 漏检约 2⁻³² / 包 64 位 BLAKE3 · 漏检约 2⁻⁶⁴ / 块
包头保护 覆盖包头（session_id / chunk_id / flags） 不覆盖包头
校验失败后的修复 丢弃该包 → 该块仍为「未收到」→ 裁决后定点补发该块 同左（修复粒度相同）
为什么两个都要：CRC32 只有 32 位，未检出概率约 2⁻³² —— 100 GB 文件约 2.1%、1 TB 文件约 20.8%， 且漏检后只能靠全文件复核轮修复；反过来只有逐块摘要也不够 —— 包头不受保护，被篡改的 session_id / chunk_id / flags 摘要照样自洽， 而它们决定的是「写到哪个偏移」「属于哪个会话」，属于协议语义而非文件内容。 与文件级 Blake3 合起来构成三层保障。
为什么单次校验失败 ≠ 整文件重传：本协议不采用逐包 ACK，而采用「位图 + 缺失裁决」。 任何一次校验失败都只是让对应的那一个块保持「未收到」； 该块会在下一次裁决（≤ 50 ms）中被精确报告，发送方按缺失列表只补发该块。 单次校验失败的代价是一个块的重传，与文件大小无关； 只有文件级校验失配才需要整文件重传（复核轮）。
校验时点：接收方在写盘前校验 chunk_digest， 因此写盘之后才发生的磁盘写入错误不在包级校验覆盖范围内 —— 它只能由文件级校验捕获并走复核轮。实现可以在写盘后回读该块重新校验以提前发现（推荐性，见 17 章）。
