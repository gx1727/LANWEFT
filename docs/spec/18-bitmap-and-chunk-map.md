# 18 位图与块图（Bitmap & Chunk Map）

## 两级位图（规范性）

寻址单位是 **chunk**，线缆/修复单位是 **symbol**（`symbol_size` = 1200）。接收方的进度
记录**必须**是两级的：

| 层 | 粒度 | 说明 |
|----|------|------|
| **块完成位图** | 每 `chunk_id` 1 位 | 该块的**所有 symbol 均已收到**时为 1 |
| **块内 symbol 掩码** | 每个未完成块一个 `u64` | bit `i` = 1 表示第 `i` 个 symbol 已收到；`S = chunk_size / symbol_size ≤ 64` 故一个 `u64` 足够 |

接收方的位图**必须**提供以下能力：

| 能力 | 说明 |
|------|------|
| **判定** | 能判定任意 `chunk_id` 是否**已完成**，以及任意 `(chunk_id, symbol)` 是否已收到 |
| **枚举（块）** | 能按升序枚举**完全缺失**的 `chunk_id` 全集（一个 symbol 都没收到） |
| **枚举（部分）** | 能按升序枚举**部分缺失**的块及其缺失 symbol 掩码 |
| **计数** | 能给出已收到 / 未收到的 **symbol** 数量（精确值） |
| **持久化** | 能把两级位图写入副本并从副本恢复（见 09 章） |

- 重复标记同一 symbol **必须**是幂等的（第二次标记不改变状态）。
- symbol **必须**在数据写入临时文件**之后**才被标记为「已收到」；
  校验失败（`crc32`）的报文**必须**不标记其覆盖的任何 symbol
  （见 12 章「缺失块的定点补发」）。
- 一个块的 symbol 掩码全 1 时，接收方**必须**置其块完成位并**丢弃**该掩码；
  块完成位为 1 后**不得**再回退为 0（除下述两级清位外）。
- **清位语义分级（规范性）**：清位**必须**按恢复阶段区分两档，**不得**混用：
  - **定点修复（摘要对帐，generation 1）**：接收方**只**把**可疑块**的块完成位清零，
    并**丢弃这些块的** symbol 掩码；**其余已完成块的完成位与掩码必须保留**。
    随后按常规缺失裁决上报这些块（见 12 章「摘要对帐」第 7 步）。
  - **全量复核（复核轮，generation 2）**：接收方**必须**把块完成位图**全部**置 0、
    **丢弃所有** symbol 掩码，然后**必须**重新计数（见 12 章「复核轮」）。
  两档清位后都**必须**按新代号从基线重新计数（见下「信用计数的可导出性」）。
- 位图的**内部组织方式**（字长、原子类型、内存布局）由实现决定，
  **不构成**互操作要求；但**必须**支持按 `chunk_id` / symbol 索引**升序**枚举
  —— 缺失列表的分批下发依赖升序（见本章「缺失列表的下发上限」）。

## 信用计数的可导出性（规范性）

两级位图**必须**能给出当前代号下**已收到**的不重复 **symbol 数**，供接收方填写
`window_update.received_symbols`（见 06、11 章）。该计数**必须**等于
`symbol_count − missing_count`，并在当前代号内**单调不减**；
复核轮或摘要对帐清位并切换代号后，**必须**从新代号的基线重新计数。

## 刷盘策略（推荐性）

- 建议每 1s 或每收到 100 个 symbol 刷盘一次
- 避免每 symbol 同步刷盘

### 缺失计算优化

- 以 u64 为单位批量跳过块完成位全 1 的区间
- 只有当 word != u64::MAX 时才逐位检查
- 块内掩码直接参与按位与/或，无需展开成 symbol 列表

## 缺失列表的下发上限（规范性）

- 单条 `missing_chunks` 中的**完全缺失块**条目**不得超过 4096 条**
  （受控制通道 `max_frame_len` = 1 MiB 的约束，见 06 章「帧格式」）。
  二进制下 `chunks` 为 `chunk_list`（`u32` 条数 + `u32` `chunk_id` 数组），
  4096 条 = 4096 × 4 = **16 KiB**，仍远小于 `max_frame_len` = 1 MiB。
- 单条中的**部分缺失块**条目（`partial[]`）**不得超过 1024 条**；
  每条 12 字节（`chunk_id` u32 + `received_mask` u64，bit=1 表示已收到；与块内位图同语义），
  1024 条 = **12 KiB**。
- 接收方**必须**按索引升序**分批下发**缺失：
  一批被补齐后，下一批在随后的裁决周期中下发。
- 载荷中的 `missing_count` 字段给出位图中**尚未收到**的 **symbol 精确总数**，
  用于发送方判断是否还有后续批次**并推算在途量**（见 11 章判据第 3 条）；
  对端**未携带**该字段时（`flags.bit0 = 0`，此时该字段**必须**为 `0`），
  发送方**必须**按「可能还有后续批次」处理，
  并采用 11 章判据第 3 条规定的保守退化策略。
- 规模估算：100 GB 文件、`chunk_size = 64800` 约 1.5×10⁶ 块（块完成位图约 190 KB），
  共约 8.3×10⁷ 个 symbol；即使缺失 1%，也只有约 8.3×10⁵ 个 symbol，
  在两级位图下按块聚合后仍**必须**依赖分批机制。
