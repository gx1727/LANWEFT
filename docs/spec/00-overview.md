# 00 概览（Overview）

LANWEFT 是面向可信局域网的混合文件同步协议。通过"控制面 TCP + 数据面 UDP"的双通道协作，在保证高吞吐的同时，实现可中断、可恢复、可裁决的文件同步能力。

## 核心特性

- 局域网内大文件（照片/视频）高效同步
- 不中断可恢复、乱序写盘、内存与文件大小解耦
- 控制与数据分离，可靠性由控制面裁决
- 完整性分层：包级 CRC32 + 文件级 Blake3
- 控制面：TCP 长连接（二进制帧格式 + 权威快照重同步）；数据面：UDP；位图进度；会话恢复；NAT 探测

## 表示形式（规范性）

- 控制面载荷为**小端二进制定长布局**：
  控制帧 = `u32 magic` + `u32 frame_len` + `u32 header_crc32` + `u8 msg_type` + `u8 flags` + `u8 body_version` + `u8 reserved` + 消息体；
  （**16 字节定长帧头**；`magic` = `0x574E414C`，`header_crc32` 用于帧同步与失步检测，见 06 章）；
  消息体 = 定长区（表格式偏移/大小）+ 变长区（顺序固定）。详见 06 章。
- 基础类型：`u8` / `u16` / `u32` / `u64` 小端；`bool` = `u8`（0/1）；
  `str` = `u16` 长度 + UTF-8（长度 0 表示无值）；`hash32` = 32 字节原始 Blake3 摘要。
- 数据面数据包的格式见 08 章，本规范不在此重复定义。

## 角色与视角

| 视角 | 定义 | 上传方向 | 下载方向 | peer 方向 |
|------|------|----------|----------|-----------|
| 发送侧 | 发送数据的一方 | Client | Server | `sender_device_id` |
| 接收侧 | 持有位图与临时文件的一方 | Server | Client | `receiver_device_id` |

- 完成消息一律由**接收方**发布（`peer_complete` 由接收方经 Server 中继）
- 缺失报告一律由**接收方**发起
- Server 拥有一般会话终止权；非 Server 接收方的终止原因限于 10 章「终止权」。

详见 10 章「视角定义」。

## 文档约定（规范性）

### 文档性质

本文件是**协议设计说明书**。正文只包含协议本身：规范要求、推荐做法与设计理由。

- **不记录修订过程**（哪一版改了什么）——
  修订历史**必须**记入 [26 章「修订记录」](26-roadmap.md)。
- **不描述具体实现**（编程语言、库、私有 API、源码路径）——
  实现细节**不构成**协议的一部分（见 25 章）。
- **不做版本对比** —— 正文陈述的是**当前**协议，
  **不得**使用「改由 / 取代 / 不再」等与前一版本对比的措辞，
  **不得**引用协议中已不存在的概念（见 25 章）。

### 规范性用语的强度

| 用语 | 含义 |
|------|------|
| **必须 / 不得** | 强制要求，违反即为实现错误 |
| **应当** | 强制要求（允许有充分理由的例外，例外**应当**有记录） |
| **建议 / 推荐** | 强烈建议，偏离时**应当**说明理由 |
| **可以** | 允许但不要求 |

- 规范性要求**必须**写在正文，**不得**藏在引用块中。
- 非规范性内容（实现建议、背景说明）**必须**显式标注为
  「非规范性（Non-Normative）」或「推荐性」，见 25 章。
- 设计理由（为什么这样规定）**应当**以「说明」小节或正文段落呈现，
  与规范性要求明确区分。

## 站点与源文（规范性）

- **规范源文是唯一真源**：本规范的正文（`docs/spec/*.md`）是协议事实的**唯一**来源。
- **站点页面是可视化导读**：站点（`docs/site/`）呈现的是本规范的可视化版本，
  并随站点一同发布**源文副本**，读者随时可读原文。
- 站点页面的内容**必须**忠实于源文；**不得**成为规范事实的来源，
  **不得**引入源文没有的结论、字段或数值。
- 站点与源文不一致时，**以源文为准**。
- 站点页面由 `scripts/render-site.py` 从源文渲染（规范正文自动渲染，
  可视化片段中的数据亦取自源文），**不得**手工转抄规范正文 ——
  转抄即漂移，漂移难以察觉（见 25 章）。
