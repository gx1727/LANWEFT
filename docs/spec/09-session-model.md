# 09 会话模型（Session Model）

## 会话参数

| 字段 | 类型 | 说明 |
|------|------|------|
| session_id | u32 | 会话唯一标识，Server 生成 |
| client_id | str | 客户端设备 ID；**必须**等于控制连接绑定的身份（见 21 章） |
| direction | enum8 | `0` = `upload`、`1` = `download` —— **接收方 / 发送方角色** |
| file_hash | hash32 | 文件哈希（**32 字节原始 Blake3 摘要**） |
| file_name | str | 文件名 |
| size | u64 | 文件大小（字节） |
| mtime | u64 | 文件修改时间戳 |
| state | enum8 | 会话状态（见 10 章） |
| chunk_size | u32 | Chunk 大小（字节） |
| window | u32 | 滑动窗口大小（**在途上限**） |
| chunk_count | u32 | 总 chunk 数量 = ceil(size / chunk_size) |
| udp_port | u16 | UDP 端口号 |
| tcp_port | u16 | TCP 端口号 |
| last_activity | u64 | 最后活动时间戳 |

**`direction` 字段是必需的（规范性）**：本协议的 `missing_chunks` 是**双向**消息，
其含义依赖会话方向（见 06 章）。Server 侧的会话记录**必须**能区分
「我是接收方」还是「我是发送方」，否则无法正确解释对端的缺失报告。

| direction | 接收方 | 发送方 | 完成消息发布方 |
|-----------|--------|--------|----------------|
| `upload` | Server | Client | Server（`upload_complete`） |
| `download` | Client | Server | Client（`download_complete`） |

## 与控制连接的关系（规范性）

- 一个 `device_id`（一条控制连接）**可以**承载**多个并发会话**；
  `session_id` 用于区分。
- Server **必须**为每个会话记录其所属的控制连接；
  连接断开时，该连接上承载的**全部**会话进入**中断**处理（见 13 章）。
- 会话**不得**跨连接迁移 —— 恢复只能通过 `login` 的恢复列表
  重新建立关联（见 06 章、13 章）。
- **数据面端口可以被多个会话共用**：UDP 包头中的 `session_id` 足以区分（见 08 章）。

## 创建规则

1. **session_id 由 Server 生成**
   - Server **必须**保证在自身生命周期内 `session_id` 唯一；
     冲突时**必须**重新生成而不是复用。
   - u32 的空间有限，实现**不得**使用裸时间戳低 32 位
     （秒级回绕 136 年、毫秒级回绕 49 天）。推荐使用
     「随机高位 + 递增低位」或 Snowflake（含机器位）等方式。
   - 冲突后果严重：`session_id` 同时是控制面关联键与 UDP 头字段（见 08 章），
     串号会导致跨会话数据污染。
2. **同文件正在同步 → 返回现有会话**
   - 「同文件」的判定键为 `client_id + file_hash`（同一客户端的同一内容）。
   - 返回现有会话时，`upload_accept` **必须**复用既有的 `session_id`，
     并重新下发当前的 `window` / `chunk_size` / `udp_port`。
3. **已存在完整文件 → 秒传**
   - Server 侧已存在相同 `file_hash` 的完整文件时，`upload_accept.file_exists = 1`（bool 真），
     走 10 章定义的秒传路径（**不进入 TRANSFERRING，不产生位图**）。
4. **否则新建会话并生成新的 session_id**

## 持久化（规范性）

接收方**必须**持久化以下状态，使其在进程重启或设备重启后仍可恢复：

- **临时文件**（含已写入的数据）
- **位图**（各 `chunk_id` 的接收状态）
- **会话元数据**（`session_id` / `direction` / `chunk_size` / `chunk_count` / 临时文件路径）

- 位图**必须**能写入持久化副本并从该副本恢复；
  持久化格式与存储位置由实现决定。
- 写入与位图更新的**先后顺序**由实现决定，但必须保证：
  位图标记为「已接收」的块，其数据**已经**落在临时文件中
  —— 否则恢复后会把未落盘的块当作已接收，导致空洞永不重传
  （见 13 章「空洞块的补发」）。

## 超时与回收

- **会话活动超时**：**60 秒**内无任何控制面交互或数据面活动的会话，
  Server **必须**将其置为 ABORTED 并清理临时文件 / 位图 / 元数据。
- **超时层级（规范性）**：控制连接的空闲超时（**30 秒**，见 06 章「心跳与超时」）
  **必须**早于会话活动超时（60 秒）触发。
  即：连接先断开（会话转为**中断**，可恢复），
  随后才由会话超时兜底清理（转为 **ABORTED**，不可恢复）。
- 客户端在超时前可经 `login` 的恢复列表恢复；超时后恢复**不合法**
  （ABORTED 是终态，见 10 章）。
- 该阈值对应 19 章的 `TIMEOUT_NO_ACTIVITY`。
